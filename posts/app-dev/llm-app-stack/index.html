应用开发 · 8 min

大模型应用开发的最小工程栈

一个可上线的 LLM 应用不只是一段 prompt，而是一套能被调试、评测和持续迭代的工程系统。

本文阅读 -- 站点访问 --

1. 模型访问层

模型访问层负责统一不同模型供应商的 API、超时、重试、流式输出、错误码和成本记录。早期可以保持简单，但接口需要稳定，避免业务代码直接绑定某一个模型 SDK。

2. 上下文管理

上下文决定模型能看到什么。常见输入包括用户消息、系统指令、检索片段、工具返回值、用户画像和历史摘要。工程上要限制 token 预算，并记录每次实际送入模型的上下文。

3. 工具调用

工具调用让模型从“会说”变成“能做”。建议把工具设计成小而明确的函数，输入输出使用结构化 schema，并对危险动作加入确认或权限控制。

4. 评测与观测

上线前至少准备一组固定用例，覆盖正常、边界和失败场景。上线后记录 prompt、模型、延迟、token、工具调用、用户反馈和失败原因，持续定位问题。

最小工程栈的目标不是复杂，而是让每次模型行为都有证据可查、有用例可回归、有指标可对比。
